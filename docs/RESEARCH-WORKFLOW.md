# 研究流程与复核

## 分析范围

领域问题先检索，研究范围保存为公开编号列表；后续统计、聚类、原文及权利要求工具只接收这份结果集。检索采用Top-K相关性筛查，不能解释为查全或行业全集。检索复核节点可剔除明显无关候选、提出新英文检索表达，最多补检索两次。每次查询、返回编号、剔除理由均保留。零结果不会退回全库。

说“继续分析上轮检索结果”可恢复同一对话上轮保存的范围；若无范围，明确告知，不替用户扩大分析。工作流为 Planner → Search → ResearchReview → Analysis → Claim → Comparison → Citation → Audit → Report。具名节点运行在单体应用内；检索复核会改变后续输入范围，但不宣称有多个独立专家或完成专业法律审查。

示例：

> 先检索数字身份认证相关专利，再只对候选集分析申请人集中度和IPC分类分布，生成报告。

> 继续分析上轮检索结果的公开趋势，不要重新检索全库。

## 权利要求对照

`compare_claims` 指定2至5个公开编号，第一个作为基准。`claim_numbers` 在全部选定文献中选择相同编号，留空则读取全部权利要求。程序逐段抽取，使用实际引文索引建立对应，不接受模型自写引文。逐项保留对应证据、部分重合、未发现及理由；页面两栏显示原文，支持筛选、原文查看及导出。

默认例题明确仅比较两项篇幅适中的真实专利的第1项权利要求。它是功能示例，不是模型挑选的相似技术或经过确认的现有技术。自行选择相关文献才能进行有意义的技术对照。候选公开较早不等于满足现有技术资格；未发现不等于全球不存在。此功能不作FTO、新颖性、创造性或侵权意见。

## 数据整理与获取

数据页提供人工申请人别名规则，每条填写 `alias`、`canonical`、`basis`，只直接映射到最终名称；原始名称、受让人与历史结果不改写。集团关系必须有依据，不自动模糊归并。

公开件/同族计数可在工具表单选择。同族按来源familyId归并，保留筛选范围内最早公开件；缺标识者独立保留，并显示缺失数量。代表件统计不是全同族汇总，尤其不能用代表件申请人字段证明集团布局。

公开语料采集从 ExponentialScience/DLT-Patents 指定位置读取，每批100条、最多10批。下载窗口保存，重试可复用；排除截断与缺全文记录，按公开编号去重。可用英文BM25词法查询筛选，保存为新数据集，另行建立语义索引。这是公开语料窗口采集，不是全球实时在线检索。

已有文献可每批最多10项补充Google Patents法律事件及同族代表公开件；保存页面获取时点及原始快照，支持停止、复用和主动重新请求。单项失败不补造资料，成功项保留。Google状态为第三方推定，不是官方实时法律状态，也不承诺完整全球同族。商业交易背景只能按真实披露范围使用；缺收益、许可和维护成本资料时仍不做单项商业估值。

## 人工质量评测

每次结束的运行都有“质量复核”入口：程序检查引文定位、图表引用与计划执行状态；人工另行标注检索相关性、抽取正确性及报告是否可接受。没有人工标注时指标为空，不拿模型自评冒充准确率。

`relevant` 和 `irrelevant` 是独立阅读原文后标注的公开编号。precision仅以已标注返回记录为分母，未标注返回单独计数；recallWithinJudgedPool只相对已标注相关记录池，不是全库或全球查全率。抽取评审每行指定resultId、从0开始的row、correct、note。报告accepted/needs_revision/not_reviewed独立记录。

可重现导出：

```sh
npx tsx scripts/evaluate-research.ts judgments.jsonl /absolute/path/evaluation.json
# 仅检查结构和证据、不伪造人工评分：
npx tsx scripts/evaluate-research.ts - /absolute/path/evaluation.json
```

`judgments.jsonl`每行结构：

```json
{"runId":"实际运行ID","reviewer":"评审人","basis":"评审范围与原文阅读依据","relevant":[],"irrelevant":[],"extraction":[],"report":"not_reviewed","reportNote":""}
```

这只是格式示例，不是黄金标注。专业准确性需要独立人员阅读并标注，功能实跑不能替代它。
