# 技术材料导入开发记录

本地M7材料处理工作，不是完整OCR或平台交付。生产未改动。

`POST /api/disclosures/extract` 接受multipart的`file`，由现有项目权限入口授权。支持UTF-8 TXT/Markdown、DOCX及PDF，文件最大10MB，提取文本最大50万字符；超过上限明确拒绝，不截断。返回文件名、格式、文本、分段/页信息、限制说明及`saved:false`、`modelAssisted:false`。这是预览，不自动保存交底书、分配字段或调用模型。

Word通过unzip与现有XML解析器提取正文，保留段落及表格阅读顺序，忽略修订删除内容；不声称保留原排版页码、图像、页眉页脚、脚注、自动编号及复杂公式。PDF通过pdftotext逐页提取文字，页码从1开始；无文字页标记`needs_ocr`，不能区分扫描页与真正空白页，均提示人工核对，不冒充识别成功。多栏和图表内容仍需查看原文件。

解析采用本次请求独立临时目录，成功或失败后清理，原文件暂不作为项目材料持久保存。进程有明确超时及取消信号；文件损坏、加密或服务器缺少解析程序时返回提取失败。服务器需要unzip与Poppler的pdftotext，未安装时不静默降级为乱码文本。

自动测试检查原始UTF-8正文、段落和表格顺序、删除修订排除、格式/空文件拒绝，以及multipart提取不调用交底存储。类型检查通过。真实本地上传60段合成Word/PDF，检查末段保留及no-store响应，没有写入现有交底书。返回Word一段结构化正文、PDF按实际分页；验收采用既有`report-word-weighted`合成文件，不引入实际研究结论。

剩余工作：原文件的授权持久存储和来源版本、材料页面及字段确认、持久OCR任务与实际扫描文件验收、附图定位和提取质量反馈、专业流程使用材料证据。解析预览不能代替这些完整链路。

## 项目材料存储

新增033迁移与`ProjectMaterials`服务。数据库保存文件名、格式、字节数、创建人、项目归属及完整提取快照；原文件使用随机材料ID存于`PATENT_DATA_DIR/materials/<projectId>`，不把用户文件名作为磁盘路径。每次上传独立保存，不覆盖其他材料。原文件权限0600，数据库保存失败时清理该次文件。上传不会自动改写交底书。

材料移除只标记`removed_at`，列表、读取与下载不再可见，原文件与提取快照保留供恢复；当前未提供永久清除或自动保留期。这个边界需要在后续页面明确标注，不称作已经彻底擦除。备份需要同时包含PG与materials文件目录，只有数据库备份不能恢复原文件。

普通非所有者PG角色实测：精确原文件读取、真实另一项目不可见、只读成员可读不可创建/移除，以及移除后活动入口不可读。相关测试及类型检查通过。033已应用本地开发库，运行角色只获SELECT/INSERT及removed_at列UPDATE权限；生产未改动。API、页面、版本关联、OCR与完整恢复验收继续开发。

## PDF按页OCR

新增`material-ocr.ts`，使用Poppler逐页渲染为150dpi PNG，再用本机Tesseract的chi_sim+eng语言识别。每页保留页码、OCR方法、语言、文本、识别状态及平均词置信度；置信度只反映程序评分，不等于准确率。无文字输出标记unreadable，不制造正文。逐页回调在继续下一页之前等待保存，可用于后续持久任务断点；目前尚未接入任务表或页面。

识别和渲染各有90秒页级超时及取消信号，结束后清理临时图像和文件。失败明确指出页码，不把已完成页面当作整个任务成功。原文件不被改写，OCR文字是衍生文本，不替代原文字体坐标或附图内容。

两项相关测试与类型检查通过。合成图像型PDF先经普通提取标记needs_ocr，再真实识别出TECHNICAL DISCLOSURE及中文技术方案，逐页回调记录第1页，平均词置信度94.6008；未进行人工准确率评估。产物`material-ocr-synthetic.pdf`及`material-ocr-result.json`、生成脚本`verify-material-ocr.mts`位于既有验收目录，未上传到项目或生产。程序依赖已经确认本机具备的Poppler、Tesseract与中文/英文语言包；生产安装仍需单独验证。

## 持久OCR任务

034迁移扩展既有jobs队列，OCR任务直接关联材料，不创建无关专利数据集、对话或运行；数据库约束区分材料任务和原运行任务的目标。活动任务按材料唯一，提交锁定材料后拒绝重复任务；缺省只识别needs_ocr页，显式页码必须属于原PDF。页面结果保存在独立material_ocr_pages中，原提取快照不被覆盖。

执行复用现有后台租约、心跳、权限与取消机制，按页保存检查点；恢复时只处理未保存页，失败/取消任务重试保留已完成页。任务状态可读完成页数与总页选择，空识别页依然保留unreadable状态，不等同成功识别文字。新任务类型已经接入worker的执行分支，HTTP提交/状态/取消、页面及真实worker联调尚待完成。

普通PG角色测试在无任何数据集或runs的项目中提交任务，验证重复提交和超范围页拒绝，人工合成页检查点经真实队列领取执行及重试后仍只保存一页；该测试验证队列恢复，不冒充实际OCR。此前单独真实OCR已通过。既有worker/队列五项回归通过。034已应用本地库并授权运行角色SELECT/INSERT页面表，生产未改动。

### OCR HTTP接口

`POST /api/materials/:materialId/ocr`提交页码选择（省略pages时选择待OCR页），返回202；`GET`同路径读取任务列表。`GET /api/materials/:materialId/ocr/:jobId`返回任务状态、请求页码及按页排列的已保存结果，标记derived=true。该读取先验证材料访问，再验证任务属于材料，不允许将其他任务ID拼接到当前材料下读取。

任务路径追加`/cancel`或`/retry`并POST可取消或续跑。取消完成任务返回cancelRequested=false，不冒充执行了取消。接口沿用项目授权和no-store响应，浏览器断开提交请求不取消已入队任务。普通角色接口专项验证覆盖页结果、错误任务关联和完成任务取消；材料原下载、分页及软删除测试保持通过。尚待页面接入、OpenAPI说明和真实后台OCR联调，不能视为材料模块交付完成。

后续已补充OpenAPI的全部OCR路径及页码、衍生结果、置信度和恢复语义，四项契约测试通过。图像型合成PDF使用`PATENT_OCR_TEST_PDF`显式启用真实集成路径：材料保存→HTTP处理器提交202→队列领取→Poppler/Tesseract识别→PG页检查点→授权读取结果，英文TECHNICAL DISCLOSURE与中文技术方案均检出，任务completed且原提取快照仍为needs_ocr。该结果证明测试进程中的真实队列执行链，不等同独立常驻worker、浏览器和生产联调。默认未提供该环境变量时不执行真实识别断言；不能将默认测试通过报告为OCR运行依赖验收。

重试与新提交共用材料行锁，存在其他活动任务时返回明确的忙碌提示，而非暴露数据库唯一约束错误。专项测试新增同一材料的任务冲突、排队取消以及通过HTTP处理器重新入队后真实识别完成。任务列表包含所有历史任务；验证按任务ID定位，不把列表最新一项误认为正在续跑的旧任务。

OCR写操作在HTTP处理器明确检查项目写入权限，只读角色的提交、取消、重试返回403；读取已授权检查点仍可用。普通数据库角色测试另验证直接绕过HTTP提交仍被RLS拒绝，恢复负责人角色后真实识别路径继续通过。此检查针对多用户平台实际支持的只读角色，不依赖前端隐藏按钮。

真实OCR集成进一步改为启动独立`scripts/agent-worker.ts`子进程：运行连接使用普通非绕过RLS角色，维护连接指向专用测试schema。提交后等待该进程实际领取任务，验证ready日志、completed状态和持久化中英文结果；随后SIGTERM正常退出并等待退出完成，再清理测试schema及文件。此次证明真实独立worker与材料OCR分支可执行，不修改已有开发worker或生产服务。浏览器进度展示、运行中取消和进程中断后的实际OCR续跑仍待单独验证。

材料移除与活动OCR取消在同一事务中执行：排队任务直接cancelled，运行任务设置取消请求由后台心跳处理；已有检查点及原文件保留。移除后结果读取和重试不可用，恢复材料后可查看原结果，但不会自动重启已取消任务。专项测试覆盖排队任务随移除取消、移除后拒绝结果/重试、恢复后检查点仍在及任务仍取消。运行中取消的实际进程停止仍待验证。
