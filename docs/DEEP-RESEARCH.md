# 深度报告

深度报告将研究与写作组织为一个持续任务。用户给出研究目标，助手了解数据、拟定研究问题和提纲，随后调用工具、读取原文、撰写与修订章节，最后将报告保存到报告库。

## 开始研究

从顶部工具栏打开“深度报告”，也可以从专业任务或分析助手进入。填写研究目标，选定数据集、目标字数和模型调用预算。

默认选择“确认提纲后自动完成”。助手先说明对用户意图、报告用途和数据范围的理解，提出待确认问题、研究路径及提纲。“按意见调整方案”可回答问题或要求重新规划，助手修订后再次等待确认。每轮方案与用户意见保留记录，可展开查看；提纲中的标题、问题和篇幅可以直接编辑。满意后点击“方案已确认，开始生成”。选择“全自动完成”时，提纲规划后直接进入研究与写作。

较长报告按多个章节完成。目标字数用于规划章节篇幅；完成时，系统检查正文是否达到完整目标，并要求有成功的分析结果。字数按汉字逐字、其他语言按词计，引用标记和链接地址不计。篇幅通过有证据的新比较、原文案例与交叉分析展开，禁止重复段落、无关背景或换词复述凑字数。达到篇幅后，助手继续判断研究问题是否已回答，并组织综合结论和摘要。

## 研究过程中

- 选择提纲中的章节，阅读已保存正文。
- 打开章节版本，对比历次修订。
- 在“补充研究要求”中指定重点、补充问题或需要加强的比较，助手在下一步读取。
- 点击暂停，保留已完成研究。后台保存当前执行状态后，可以继续。
- 调用预算耗尽时，已写章节和结果仍保留；调整预算后继续研究。

完成后，点击“阅读完整报告”进入报告库，使用现有导出、分享和复核功能。重新进入研究记录时，正文直接显示。

## 执行方式

引擎采用 Deep Agents JavaScript，使用 LangGraph 检查点保存消息、工具调用中断和研究笔记。工作区文件使用状态后端，随检查点存入 PostgreSQL。新增补充意见作为独立用户消息交给助手，接收记录与检查点一起保存，恢复后按进度继续。

研究工具包括：读取任务状态、保存与确认提纲、调用系统分析工具、分页读取完整结果、阅读专利原文、读取和写入章节、组装保存报告。助手自主选择分析顺序，依据章节发现补充研究；已写章节保留编号，可以调整标题、顺序、问题和篇幅。

专利原文引用保存公开编号、字段、字符位置、原文片段和来源链接。分析结果保留完整数据及研究范围。章节写入前检查图表和证据编号，报告组装时统一编号来源。章节中的通用免责声明、人工复核提醒与附加缺失字段说明会退回助手修订；原文资料保持原样。

任务沿用项目权限、组织模型配置、持久后台队列、租约恢复和模型调用预算。消息压缩与主模型请求均通过同一个模型适配器计入用量。章节与报告通过数据库事务保存。

## 阅读约定与工具边界

技能说明如何研究和判断，工具约束实际读取。助手的工具目录会提供每项分析的执行方式、资料选择要求及阅读建议。

- **全库统计**：趋势、分布、集中度及网络计算可以覆盖明确的数据全集。结果先返回20行预览，后续按研究问题分页读取。核查单件专利所属主题或统计分组时，使用 `read_result` 的 `patent` 参数精确匹配成员记录，并保留原始行号。预览中省略的数组会注明实际数量；完整结果保持原样。
- **证据复用**：证据目录列出原阅读问题、公开编号、字段、偏移和片段长度；使用 `read_evidence` 恢复已读原文。已有片段足以回答时转入比较与写作，缺少上下文才读取新位置。
- **原文片段**：`read_patent` 必须明确 `question`、公开编号与字段（摘要、权利要求或说明书）；默认2500字符，最多12000。寻找明确词句可用 `find` 在所选字段内字面定位，返回真实偏移；未找到返回 `found:false`。证据足以回答问题时停止，需要上下文时按 `nextOffset` 续读；返回空值表示该字段读完。原文读取不额外调用模型，保存问题、引文和位置。
- **全文模型整理**：技术效果矩阵、专利全文研读、权利要求要素和权利要求对照必须用 `patent_numbers` 显式指定，每批1至5件；对照至少两件，第一个为基准。这类工具按未缓存分段调用模型并计入预算。只需几段文字时直接读片段；需要系统全文整理或逐项对照时再用这些工具。
- **语义检索与主题命名**：语义检索使用查询向量；聚类计算后另有主题命名模型调用。检索Top-K用于定位案例，统计结论使用实际统计范围。

长报告结合全库分布和有依据的代表案例。矩阵解释对应所选原文，不能把案例结果写成全库效果频率。研究资料区可回看每段原文对应的问题与来源。

## 可复用研究技能

项目在 `skills/research/` 维护六项 Agent Skills，使用标准 `SKILL.md`，由 Deep Agents 按描述发现并按需读取：研究规划、专利全景分析、专利原文研读、证据驱动写作、事实核对与修订、中文表达整理。技能说明对应何时调用哪些工具、如何读取证据，以及如何交付章节。中文表达整理仅定向修改套话与句式，保留事实、限定、结构和原文引文。

研究状态展示当前调用的技能，工作区提供技能目录。规划和修订使用原任务的模型预算。技能目录只读挂载到 `/skills/`，研究笔记仍保存在任务状态中；发布包需要包含 `skills/research/`，现有运行时构建脚本会复制。

## 接口

所有接口使用当前项目身份，也接受有对应权限的项目 API 凭据。

| 操作 | 接口 |
| --- | --- |
| 创建任务 | `POST /api/research-tasks` |
| 研究记录 | `GET /api/research-tasks` |
| 提纲、正文与来源 | `GET /api/research-tasks/:id` |
| 讨论并调整方案 | `POST /api/research-tasks/:id/revise-outline`，提交 `{"text":"调整意见"}` |
| 确认提纲 | `POST /api/research-tasks/:id/confirm-outline` |
| 暂停 | `POST /api/research-tasks/:id/pause` |
| 继续 | `POST /api/research-tasks/:id/resume` |
| 补充要求 | `POST /api/research-tasks/:id/feedback` |
| 章节版本 | `GET /api/research-tasks/:id/versions/:chapterId` |

创建参数：

```json
{
  "datasetId": "当前项目中的数据集编号",
  "goal": "分析该领域的技术演进、主要主体与代表方案，提出下一步研发问题",
  "mode": "confirm_outline",
  "targetWords": 20000,
  "maxModelCalls": 120
}
```

`mode` 可选 `confirm_outline` 或 `automatic`。确认提纲可提交 `outline` 数组，每项包括 `id`、`title`、`question`、`targetWords`。补充要求提交 `{"text":"需要补充的内容"}`。调用预算沿用 `GET/PATCH /api/runs/:id/budget`。

迁移 `046_research_planning` 为研究任务增加需求理解与方案历史。调整方案从原生中断点恢复，并将调整请求交给助手；再次保存方案后重新等待确认。
