## 修复内容

| 问题 | 改动 |
| --- | --- |
| Skill 被当作待修改稿件 | 明确技能只读；误改时指向 `write_chapter`，报告正文与工作笔记分别保存。 |
| 相同章节重复增加版本 | 直接比较正文、发现和证据集合；没有变化就沿用版本，不再追加快照和阶段记录。 |
| 研究过程缺少可回溯记录 | 每次有效章节保存同步记录发现及证据；具体研究缺口继续由 `record_research` 记录。 |
| 全文抽取挤占写作预算 | 技术效果矩阵执行前按实际未缓存分段计算最低调用量，为剩余章节及最终交付留出调用空间。 |
| 工具目录与直接调用混淆 | 目录名称明确作为 `run_analysis.name`；首次提纲允许没有变更说明。 |
| 只凭章节摘要宣布完成 | `read_report` 返回当前全文、来源目录与版本；`finish_report` 要求核对结论和完整版本，修改后的旧版本不能交付。 |
| 交付阶段持续扩写或润色 | 全部章节保存后明确进入交付阶段，仅处理影响事实、证据或推理的问题。 |
| 无法补齐的资料条件阻塞交付 | 可明确记录“补证解决”或“限定结论处理”及理由；后者保留实际资料缺口，页面显示处理方式。 |
| 报告列表等待工具目录和专利列表 | 历史记录独立加载，对话与报告并行读取。 |
| 数据解读错误 | 修订技能补充多标签、Top-K、年度升降、突现词字段和比较条件的具体规则。 |
