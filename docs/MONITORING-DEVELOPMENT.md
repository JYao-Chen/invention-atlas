# 监测订阅与变化通知开发记录

## 当前交付范围

本地已实现个人监测订阅、到期调度和站内变化通知，对应完整计划的 M6 部分工作。监测对象为已入库数据的检索返回集。外部数据连接器尚未接入，订阅执行前不会自动同步新的专利资料；本阶段不提供全球新公开或法律事件实时监测。

生产数据库和服务未切换。以下验收均在本地 PostgreSQL 开发库或独立测试库完成。

## 订阅与权限

订阅保存数据集及检索表达，可设置公开年份、申请人或 IPC 前缀，并指定返回数量和计数口径。执行间隔以小时为单位，允许 1—8760 小时。新建或恢复订阅后立即到期，由后台扫描提交。

订阅属于发起者及当前组织、项目。列表和通知只显示本人的项目内资源。项目 owner 或 analyst 可以创建和执行；reader 不能创建、修改或删除订阅。运行时使用非表所有者数据库角色，由行级权限限制跨组织及跨项目访问。

用户可以暂停、恢复、调整执行间隔，或立即提交一次监测。删除订阅时保留原运行和已有通知。检索策略折叠表单支持修改参数和查看历史版本；调整小时数不会重写已经安排的下一次到期时间。

策略修改请求提交完整 params 和 expectedRevision。修改检索表达、范围或返回数量后保存下一版，并立即安排到期；不改变参数的重复保存不增加版本。已有未结束任务时拒绝改变策略。并发修改中只有一个旧版本请求能成功，其余要求重新读取。各版参数不可原位更新；改回先前参数仍保存新版本并重新建立基线。

页面历史版只读，“以此版本编辑新策略”把历史参数复制到新策略表单，不覆盖原版。切换版本或刷新前，未保存的修改需要用户确认放弃。保存发生版本冲突时保留输入；读取历史发现服务器已有新版本后，先禁用编辑并提示刷新。只读成员没有保存和复制编辑入口。

## 调度与运行

`scripts/agent-worker.ts` 每隔约 30 秒扫描到期订阅。扫描使用维护连接，提交和业务执行切换为订阅者身份。账户停用或失去 owner/analyst 权限后，后台不再为其提交新任务。

扫描在取最多 100 个订阅前排除已有未结束运行的订阅，避免运行中的任务占满扫描名额。提交事务锁定订阅，再次核对启用和到期状态，创建对话与持久任务，并保存最近运行和下次到期时间。并行扫描同一订阅只提交一次。

第一版订阅使用 `subscription:<id>` 基线标识，以保留已有第一版基线。后续版本使用 `subscription:<id>:v<revision>`，修改范围后首次执行建立新基线，不把范围变更算作新增或移出。相同检索表达的不同个人订阅不会互相覆盖基线。已经有未结束任务时，立即执行接口拒绝重复提交。

扫描与队列执行共用 worker 主循环，长任务会推迟后续扫描。因此，间隔表示到期安排，不保证精确到某一秒执行。到期扫描错误记录在 worker 日志；尚未实现失败退避及邮件投递。运行失败通知的源码和页面已接入，本地 worker 已加载，并完成数据不足通知的真实调度和页面重试验收。

## 数据结构与接口

新增迁移为 019—022，分别建立订阅、最近运行引用、通知快照及策略版本。022 为已有订阅保存第一版参数，新建订阅同时保存第一版。订阅数据集删除后订阅级联删除；订阅删除后策略版本级联删除，通知关联置空；运行编号保存在通知中但不设置删除级联，因此通知证据可以独立保留。

| 接口 | 用途 |
| --- | --- |
| `GET /api/monitor-subscriptions` | 当前项目本人的订阅 |
| `POST /api/monitor-subscriptions` | 创建订阅及检索参数 |
| `PATCH /api/monitor-subscriptions/:id` | 启停、调整间隔或用 expectedRevision 保存完整策略参数 |
| `GET /api/monitor-subscriptions/:id/versions` | 本人的策略历史版本 |
| `DELETE /api/monitor-subscriptions/:id` | 删除个人订阅 |
| `POST /api/monitor-subscriptions/:id/run` | 提交持久化监测任务 |
| `GET /api/monitor-notifications?page=N&unread=0` | 分页通知、全量未读数及原运行是否仍可打开；unread=1 只返回未读 |
| `PATCH /api/monitor-notifications/:id` | 标记已读，请求为 `{"action":"read"}` |

运行角色需要订阅表读写权限、策略版本表 SELECT/INSERT 权限。通知表授予 SELECT/INSERT，UPDATE 仅授予 `read_at`、`archived_at` 列；业务接口不允许改写通知快照。维护角色仅用于迁移、调度扫描与队列维护，不作为 Web 业务连接。
