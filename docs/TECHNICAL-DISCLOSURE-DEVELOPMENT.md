# 技术交底与查新衔接开发记录

## 当前范围

本地已提供结构化技术交底材料、保存版本、缺项问题及 Markdown 草稿。材料可以按保存版本创建方案查新任务，后续修改或删除交底材料不改变已经创建的查新方案。此项对应 M7 的研发辅助部分，不表示研发平台整阶段完成。

正文由用户填写，草稿按字段整理原材料。模型目前只用于提出补充问题，不生成交底书正文，不补写实验数据或技术措施。附图入口保存名称及文字说明，尚不接收图像文件或解析附图。

## 材料与版本

表单包含技术领域、背景技术、技术问题及技术方案，另可添加实施方式、技术效果、附图说明和替代方案。效果按预期或用户声明的实测分类；实测效果缺少依据时列为必需补项，不转写为已经核验的实验结果。

材料不完整时允许保存。技术领域、背景、问题、方案及至少一种实施方式齐备后，生成八节草稿；草稿保留用户原文引用块，缺少的可选字段仍明确说明。字段齐备仅表示具备整理草稿的输入，不认证公开充分性或可专利性。

每次保存创建新的不可变版本。修改请求携带 `expectedRevision`，已有新版本时拒绝覆盖，要求重新读取。历史版本从该版快照读取标题和正文，不套用最新标题。项目内 reader 可以阅读，不能保存或删除；跨项目访问由 PostgreSQL 行级权限限制。

## 补充问题

保存版本可以请求模型生成最多八个补充问题。每个问题必须关联本版原文中的实际片段，返回字段、原句及字符位置。模型引用无法在对应片段定位时，最多修正一次，继续失败则返回错误。空材料不调用模型，超过当前输入容量时明确拒绝，不静默截断材料。

问题仅作预览，不修改或自动保存材料。用户修改输入或切换版本后，页面清除旧问题，避免把另一版证据当作当前输入。原句可定位并不证明问题专业质量，仍需要跨领域样本评估。

## 创建查新任务

创建时选择当前项目可访问的数据集及交底保存版本。技术方案少于 20 字符时拒绝创建；方案内容与实施方式合计超过 5 万字符时要求整理后再提交，不截取前半段。

查新输入包含方案名称、技术方案、实施方式，以及用户提供的替代方案。背景技术和技术效果不并入待检索方案，避免把用户描述的现有技术或预期性能当作本方案技术特征。

任务保存交底编号、版本及标题，并核对任务方案与该版本材料一致。进入现有方案查新流程后，技术特征、检索策略和候选文献按阶段确认。报告写明方案来源及保存版本，产物保留来源标识。随后修改或删除交底材料，报告仍使用任务创建时的快照。

该流程形成研究辅助底稿，不作正式新颖性、创造性或 FTO 法律判断。

## 数据和接口

018 迁移建立 `technical_disclosures` 与 `technical_disclosure_versions`。材料表保存当前标题和版本，版本表保存完整材料、缺项问题及草稿快照。删除材料级联删除版本；已创建的专业任务保留自身方案快照。

| 接口 | 用途 |
| --- | --- |
| `GET /api/disclosures` | 当前项目材料列表 |
| `POST /api/disclosures` | 保存第一版材料 |
| `GET /api/disclosures/:id?revision=N` | 指定保存版本 |
| `PATCH /api/disclosures/:id` | 核对 expectedRevision 后保存新版本 |
| `DELETE /api/disclosures/:id` | 删除材料及其保存版本 |
| `GET /api/disclosures/:id/markdown?revision=N` | 下载指定版本草稿；必需材料缺失时拒绝 |
| `POST /api/disclosures/:id/questions` | 针对指定 revision 生成补充问题预览 |
| `POST /api/disclosures/:id/novelty` | 将 revision 和 datasetId 绑定到新查新任务 |

## 验证边界

最新完整自动测试 248 项及生产构建通过。相关测试覆盖缺项规则、原文引用、效果分类、不可定位引文拒绝，以及版本冲突和权限隔离。查新集成测试验证第一版创建任务后修改并删除原材料，任务方案和报告来源仍指向第一版；模型正文在该项集成测试中使用替身，不代表真实模型报告质量。

现有本地浏览器验收脚本为 `verify-disclosure-ui.mjs` 和 `verify-disclosure-novelty-ui.mjs`，位于 `artifacts/invention-atlas/pg-migration/browser/`。这些脚本用于材料保存、旧版读取、问题预览和创建查新任务；本次监测验收没有重跑这两项，不把脚本存在当作本轮浏览器通过记录。
