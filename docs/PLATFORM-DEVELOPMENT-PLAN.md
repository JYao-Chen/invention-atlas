# 专利分析平台完整开发计划

版本：规划稿 1.0；日期：2026-10-11。适用项目为 `/home/yao/projects/apps/invention-atlas`。

本文规定从 PostgreSQL 迁移开始的开发顺序，覆盖多用户平台、专业专利任务及持续情报服务。当前线上系统继续运行，所有新增功能先在本地独立环境开发和验收，再按阶段发布至生产。本文是实施计划，不表示所列功能已经开发，也不授权直接切换生产数据库。

## 目标与交付边界

平台最终支持从技术方案或研究问题进入任务，在项目内积累检索策略和专利证据，完成专业分析，生成可编辑报告，并持续追踪相关技术与企业。多用户能够在受控权限下协作，长任务不依赖某个浏览器会话持续打开。

对标范围包括星智 Agent 的专业流程与阶段参与，以及智慧芽的检索分析、项目专题库和情报服务。功能覆盖目标与质量领先目标分别验收。商业数据采购和法律数据完整性需要独立解决，增加工具或扩充样本不能替代这些条件。

“达到”指本计划所列任务能够完整执行，过程和产物通过验收。“超过”限定在可验证的方面，例如证据定位、任务复现、开放集成和自定义研究流程；只有取得合法可用的竞品访问、在相同任务与数据条件下比较，才能声明对应指标领先。官网宣传的速度和准确率不作为已经验证的基准。

## 技术架构

保留 Next.js 和现有 TypeScript 工具。PostgreSQL统一承载业务状态，pgvector承载向量。原始文档与较大的导出文件放在应用管理的文件存储中，数据库保存路径、权限和来源信息。初期使用同机持久文件目录；需要多实例共享文件时再引入对象存储。

```text
浏览器：项目 / 分析助手 / 证据阅读 / 报告 / 管理
  ↓ HTTPS + SSE
Next.js API：身份与授权 / 项目服务 / 任务提交 / 结果读取
  ├─ PostgreSQL：用户、项目、专利、任务、报告、事件
  ├─ pgvector：记录与全文段落向量
  ├─ 文件存储：导入材料、原始文档、导出文件
  └─ 持久任务队列 → 独立worker → 26项工具 / 模型 / 数据连接器
```

worker先采用独立 Node 进程与 PostgreSQL任务表。任务领取通过事务锁定，执行在事务之外进行；保存阶段产物后再推进状态。此方案适合先完成持久任务，不预先引入Redis、Kafka或多个业务微服务。负载实测证明单库队列不足时再调整。

`src/server/db.ts` 的同步接口将改为异步访问。调用方包含API和工具模块，不能只替换数据库文件路径。SQLite专用JSON函数、触发器及插入语法必须逐项改写。轻量投影由查询列或应用服务生成，避免继续保存一份自动触发维护的完整专利副本。

数据库连接采用 `pg` 的连接池和参数化SQL；schema演进采用版本化SQL文件与 `schema_migrations` 表。迁移工具仅服务本项目，生产切换后应用不维持SQLite/PG双后端，也不长期双写。

## 第一阶段 PostgreSQL 迁移

### 环境和迁移范围

先建立专用本地开发库及一次性测试库，使用独立角色。PostgreSQL主版本与pgvector版本在本阶段核验安装兼容性后固定，本地和生产使用相同版本组合。不复用TCM-Foundry的数据库或角色，不把生产连接串装入开发配置。

开发配置计划增加 `DATABASE_URL`；这是待实现配置，当前应用尚不支持。连接串只保存在私有环境文件。SQLite读取器只作为离线迁移程序保留。

首阶段迁移现有业务并预留组织归属，避免同时重写所有高级业务。专利基础字段转为可查询列，原始来源内容保留JSONB。工具结果与历史报告仍保留快照；项目、权限和全文段落在后续版本逐步增加。

### 原表处理

| SQLite原表 | PostgreSQL处理 | 保留要求 |
| --- | --- | --- |
| datasets | 数据集及默认组织归属 | ID、名称、来源、抽样说明和创建时间 |
| patents | 公开版本记录及数据集关联 | 原编号、全文、字段及数据集成员关系 |
| patent_analysis | 不搬成业务主表 | 从主表生成轻量分析查询，核对旧投影语义 |
| conversations | 对话；归入默认用户/组织 | ID、标题、数据集及排序时间 |
| runs | 运行主表，保留原快照 | 问题、计划、范围、结果、正文及状态 |
| events | 事件表 | 原事件序号及顺序；导入后重设序列起点 |
| results | 结果表及运行关联 | 行、图谱、逐行来源、计数口径 |
| reports | 报告及不可变分析快照 | 删除对话后仍能读取和导出 |
| monitors | 监测基线 | 策略、数据集与范围独立，不混作新增 |
| settings | 拆分系统设置与用户偏好 | 活跃数据集不再是所有用户共享的全局值 |
| sessions | 不搬登录令牌 | 切换后重新登录，创建可归属用户的新会话 |

原编号和文本ID继续保留，不要求所有历史记录改UUID。检查历史孤立关系；能恢复关联则补齐，不能恢复则保留为明确标记的历史快照，不能静默删除或伪造父记录。

模型配置当前还有私有文件。首阶段保留该文件的服务端读取方式；迁移多用户模型策略时再明确组织凭据和用户自带凭据的存储，不把密钥混入普通设置导出。

### 实施步骤

1. 盘点实际表、记录数量和关联；检查直接数据库访问点，列出异步改造的调用方。
2. 创建本地PG库、角色与迁移脚本；建立默认组织及现有管理员归属。
3. 实现异步数据库服务，按数据集、专利、运行和报告分组改造调用方；保留公开API行为。
4. 用SQLite一致性快照离线导入开发迁移库。禁止从正在写入的数据库文件直接复制得到不一致样本。
5. 验证全部迁移记录的ID和业务字段，比较数组与文本内容；数值按明确精度比较，不生成无用途的哈希清单。
6. 验证已有向量数量、维度及数值。可以确认嵌入模型的记录直接迁移；来源模型不明的向量不得与新向量混用，先标识待确认，不默认删除或全部重嵌入。
7. 将测试切到独立PG测试库，验证26项工具与各API；通过迁移演练和完整恢复测试。
8. 在本地运行完整应用，验证登录、历史恢复、SSE、导出和增删改查；再准备生产切换。

### 首阶段验收

- 除明确退出旧会话外，迁移不丢失用户业务数据；全部差异有记录和处理结论。
- 专利全文和权利要求保持原文；图谱及报告快照可恢复，旧HTML导出仍可生成。
- 空范围不扩大到全库；同族与公开件口径保持；现有统计样例在相同数据上结果一致。
- 新数据写入PG后可以从备份恢复；连接中断和事务失败不留下半批导入或半批删除。
- 完成独立环境恢复演练，才允许生产切换。

## 多用户与权限

### 用户生命周期

支持邀请注册、登录退出、密码修改、管理员重置和账号禁用。首版不开放匿名注册，已有管理员通过一次性初始化成为平台管理员。邀请有失效时间，用后失效。邮件服务未接入时由管理员提供邀请链接，不能假装发送成功。

采用用户会话替代当前共享登录凭据。公网多用户场景必须有密码安全存储、会话撤销以及基本登录限速；这是此阶段实际访问风险的要求。组织管理员禁用成员或撤销分享后，API与正在读取的事件流应停止授权访问。

### 角色与操作

平台管理员维护平台配置、数据连接器和账号状态，不默认获得所有组织私有文档的日常浏览权限；需要支持访问时留下明确记录。组织角色和项目角色分别判断，项目不能放宽组织边界。

| 角色 | 成员管理 | 修改项目数据 | 执行分析 | 编辑证据/报告 | 删除项目 | 阅读与下载 |
| --- | --- | --- | --- | --- | --- | --- |
| 组织管理员 | 本组织 | 授权项目 | 是 | 是 | 授权项目 | 授权资源 |
| 项目负责人 | 项目成员 | 是 | 是 | 是 | 是，确认后 | 是 |
| 分析成员 | 否 | 按授权 | 是 | 是 | 否 | 是 |
| 只读成员 | 否 | 否 | 否 | 否 | 否 | 授权产物 |

删除数据集、批量删除和成员移除继续保留明确确认。后台权限检查覆盖资源详情、结果分页、SSE订阅、文件下载、向量召回及任务启动。仅隐藏前端按钮不能作为授权。

组织归属和项目权限在查询前加入限制，不从全库检索后再过滤用户可见记录。跨组织文档、向量与结果不得泄漏。RLS作为组织边界的数据库约束，连接使用非表所有者且不具备BYPASSRLS权限；事务内设置组织上下文，避免连接池复用串租户。系统迁移与运维角色独立。项目成员细分权限由应用服务执行，并配套跨组织、跨项目的反例测试。

## 项目与数据模型

### 核心实体

| 实体组 | 主要表 | 关键约束 |
| --- | --- | --- |
| 身份 | users、organizations、memberships、sessions、invites | 组织成员唯一；会话可撤销 |
| 项目 | projects、project_members、project_datasets | 项目属于组织；关联数据集有明确授权 |
| 专利 | publications、dataset_publications、patent_sources | 公开版本和数据来源分开；同一来源内编号去重 |
| 原文 | patent_sections、patent_chunks、embeddings | 片段定位到原文版本、字段与起止位置 |
| 分类 | taxonomies、tags、patent_tags、notes | 分类属于项目；AI建议与人工确认区分 |
| 研究 | search_strategies、search_runs、candidate_sets、evidence_links | 策略有版本；候选集和证据引用可追溯 |
| 任务 | jobs、job_steps、job_events、stage_artifacts | 阶段状态持久保存；事件可从游标续读 |
| 报告 | reports、report_versions、report_citations | 已发布版本保留快照；编辑形成新版本 |
| 监测 | monitor_strategies、monitor_runs、subscriptions、notifications | 基线按策略版本及范围保存 |
| 运维 | model_usage、activity_logs、schema_migrations | 模型用量可归属任务；记录关键管理操作 |

采用字段列和关联表承载筛选关系；JSONB保留异构工具结果和来源扩展。避免把整个项目或任务塞进一个不断覆盖的大JSON。历史报告保持原快照，不随专利修改改写。

私有导入材料按组织隔离，不在不同组织之间默认去重或共享。明确授权的公共专利数据可以形成公共数据源，项目用成员关联引用；公共与私有来源不能混成一个无归属文献集合。

索引围绕实际查询建立，包括组织/项目、公开编号、日期与IPC、任务状态、事件游标和向量过滤字段。生产SQL须分页；统计服务逐步用SQL聚合或分批计算替代一次加载全库。先验证典型查询，再添加索引。

### 项目界面

项目包含概览、专题库、检索策略、任务、证据和报告。现有工具工作台保留为专家入口，助手和历史放在项目内；个人未归档分析有明确收件区，不把用户强迫塞入某个已有项目。

专题库支持多层分类、手工标签、筛选收藏和批量编辑。AI标引先给出建议与依据，用户可以确认、改写或撤销。项目数据变更后标记已有分析快照的时间，不自动把旧报告包装成最新结果。

## 全文检索和证据

### 分段与索引

先按原文结构切分摘要、权利要求、说明书与实施例。独立权利要求尽量保持完整，从属关系另外建边；长段落再按长度拆分。初始试验可用约800—1200 token片段和少量重叠，最终设置由检索样例决定，不固定切分所有文档。

片段记录原文版本、章节类型、段落/权利要求号、起止位置、语言和来源。OCR或译文是衍生文本，不能把译文位置当作原文位置。文档修订后旧引用继续指向旧版本；新索引与原文版本一起发布。

记录级与段落级向量分开保存，索引声明模型、维度和分段版本。相同模型的现有向量可保留；切换模型时另建索引，不能比较不同模型空间的分数。索引任务按批保存进度，失败只重试未完成批次。

### 检索链路

字段条件先限定组织与项目范围，结合关键词和向量召回，再融合排序；需要时加入重排。API明确返回匹配类型、得分、候选范围与分页，不把Top-K称为全部命中。

布尔语法支持AND/OR/NOT、括号与字段约束；无效表达式返回可定位错误。中英文技术词需要独立测试；不能把PostgreSQL英文全文检索配置直接当作中文分词方案。首轮比较中文技术词的词元或字符召回方案，再决定是否需要专门搜索引擎。

同族或引证追踪需要完整数据，缺失时说明可扩展范围。语义检索、布尔检索和追踪检索分别保留策略与结果，合并后去重并记录命中路径。

每个证据对象保存“结论/特征—工具结果行—专利—原文片段”的关联。点击引用打开确切段落；逐字引用与原文一致。技术解释、模型命名和统计观察在界面中分别标识。

## 专业 Agent 流程

### 任务类型与执行方式

标准任务使用版本化Skill定义，包含输入、必需字段、步骤、阶段产物和验收规则。探索任务允许依据已完成结果追加步骤，但保持研究范围可见。保留“分析准备完成后再撰写报告”的路径，避免边写结论边改变统计口径。

| 首批Skill | 输入 | 主要阶段 | 产物 |
| --- | --- | --- | --- |
| 技术全景 | 领域或专题集、年份、计数口径 | 范围确认→检索/筛选→趋势分类→主题及主体→证据→报告 | 范围清单、图表、代表证据、全景报告 |
| 竞争主体分析 | 企业集合、领域、时间 | 名称确认→组合分布→演进/合作→代表专利→报告 | 主体映射、竞争矩阵、样本限制 |
| 技术方案查新 | 方案文本或文档、目标边界 | 方案总结→特征提取→要素编辑→多策略检索→文献确认→逐特征对比→报告 | 检索底稿、对比文件、证据矩阵及评述 |
| 专利深度阅读 | 指定公开版本、阅读目标 | 结构解析→权利要求关系→问题/手段/效果→实施例/附图→证据核对 | 阅读笔记、技术特征与原文链接 |

第二批增加技术交底书、布局候选分析、竞对简报和技术简报。每类任务先完成一个端到端样例，再推广到更多领域。FTO以风险筛查底稿起步，需目标地域及有效权利要求证据；未经专业核对不输出“可以自由实施”的结论。

### 任务状态与阶段修改

状态采用 `queued → running → awaiting_confirmation → running → completed`，并有 `failed / cancelled / interrupted`。阶段产物有版本，确认操作指向具体版本。用户修改上游范围或要素后，标记依赖产物过期，重新执行受影响步骤，不把旧比较结果继续当作有效依据。

流程保存研究目标、确认范围和未完成问题，不仅拼接最近几轮聊天。阶段继续执行从持久记录恢复。停止发生在执行节点边界或支持取消的请求中，界面显示已保留产物；重试不重复已完成的无关计算。

同一任务只能被一个worker有效领取，租约失效后可重新领取；长调用在数据库事务之外运行。任务执行成功但产物未提交时，应按步骤的实际幂等性恢复。邮件发送、外部写入等步骤不能盲目重试，保存投递记录并避免重复交付。

## 前端与报告

保留当前整体样式，先完善信息组织。发起任务立即展示问题和可展开过程，不等待规划接口返回。队列、规划、工具执行和证据准备分别显示真实阶段状态；已完成产物可按需查看。这里展示执行记录，不要求模型输出内部推理。

任务需用户确认时，正文内显示可编辑阶段产物和“确认并继续”。确认入口覆盖范围、检索要素及对比文献，避免重新加入此前已删除的通用报告复核表单。

正文在统计与证据准备后流式生成，完整图表引用出现后插入真实图表；结束后补齐未引用结果。模型可以选择可用指标和视图，不能生成没有结果支持的图形数据。长表、词云与网络仍可交互，保留数据与图片下载。

报告保存不可变版本；章节编辑形成草稿版本。引用依据未变则沿用，依据已改则提示重新核对，不能静默换成另一个专利。版本比较同时展示正文变化、范围变化和结果版本。HTML保持离线交互，Markdown保留文本；DOCX/PDF作为正式交付格式在模板稳定后实现。

上传技术材料支持正文和文件。先提供文本、DOCX与PDF提取，扫描材料需要OCR并展示提取质量；无法解析的页面明确标记。附图解读保留图像页及图号，不凭描述补造结构。

管理界面包含组织成员、项目授权、数据连接器和模型用量。管理员操作与普通研究界面分开。电脑和手机均覆盖提交、阶段确认、阅读证据及报告分享；只读成员不能看到可执行的编辑入口。

## 数据服务与持续监测

每个连接器声明授权范围、字段、更新频率、请求额度和错误处理。未购买的数据接口不写成已经可用；网页公开补充仍保留获取时点与第三方性质，不代替完整法律数据。

更新采用导入批次和源记录版本；公开编号规范化、去重和同族定义分别记录。新公开、元信息修订、法律事件及数据撤回分别处理。未知法律状态保持未知，不用模型补齐。

监测策略属于项目，保存检索表达和关注主体。每次运行先同步数据，再对当前策略版本的基线比较，形成变化集合；没有更新的数据源不能生成“外部新增专利”简报。竞对简报按企业组织，技术简报按项目技术分类组织，引用新增专利的实际原文证据。

通知先实现站内订阅，再接邮件；其他渠道按需求接入。失败显示投递状态，可重发但不重复推送同一变化批次。成员退出或授权撤回后不再接收该项目内容。

## 质量验收

### 功能与权限

已有151项测试迁入PG测试环境并继续维护；新增测试按具体失败设计。跨组织访问、只读用户写入、SSE订阅和下载绕过权限都应被拒绝。多步骤失败不能静默显示完成；历史报告在原对话删除后保持可用。

浏览器验收覆盖1440px电脑与390px手机，另检查中间宽度。任务提交采用延迟接口验证即时反馈，长任务确认采用真实阶段产物，不能只用截图证明可执行。网络断开后按事件游标恢复，不重复正文或丢图表。

### 专业效果

建立开发样例与独立留出样例，避免把同一套例子用于调提示词和宣称效果。首批建议至少50个跨任务样例，覆盖中文/英文、分类与年份约束、方案检索和原文对比；数量是启动目标，后续按领域扩充。

| 指标 | 核对方法 | 初始验收目标 |
| --- | --- | --- |
| 范围与工具选择 | 核对明确条件及所需任务 | 明确限制不被改变；失配样例必须修复 |
| 检索召回 | 在有人工相关池的样例测Recall@K与精度 | 报告K、池构建方法和遗漏；不以Top-K推算行业召回 |
| 证据定位 | 对公开编号、字段及片段逐项核对 | 所有正式逐字引文能定位，错误引用为阻断项 |
| 特征抽取 | 人工标注特征与依赖关系，计算P/R/F1 | 分任务报告，不用JSON合法率替代准确率 |
| 报告事实支持 | 人工判定每项可核对事实是否有依据 | 初始目标≥95%；重大无依据结论不得进入交付版本 |
| 阶段恢复 | 任务运行中重启worker并继续 | 不丢确认记录，不重复已交付产物 |
| 任务完成 | 全路径实际操作与产物检查 | 每个承诺场景有成功及失败样例 |

专业效果目标是待验证指标，不是当前成绩。涉及新颖性、创造性或FTO的专业判断需要具备相关经验的人员复核。用户无需进行通用打分，但项目开发验收必须保留核对依据。

“超过竞品”采用合法访问下的配对评估：相同问题、输入材料和可比数据范围，记录产品版本、模型、时间和费用。未达到同数据条件时只比较可观察的操作功能，不比较检索召回。质量差异报告样例和不确定性；无法证明优势则保持“功能覆盖达到、质量领先未验证”。

### 性能与容量

先记录开发及生产硬件和负载，再定容量。首轮用现有规模、1万条专利及10万段落逐级验证；后续依据数据接入扩大，不宣称已经支持百万量级。测普通筛选、组织过滤后的向量查询、并行索引及多个用户任务。

规划目标为提交后的本地页面反馈P95不超过300毫秒；接收任务响应P95不超过1秒，不包含模型规划。检索目标先按固定硬件、并发与数据规模记录，再设退出阈值。记录模型调用耗时、token和实际计费，不把生成的字数当作质量。

## 本地开发与生产发布

### 工作路径与环境

继续在唯一开发仓库工作，阶段任务使用Git分支；不复制final/v2项目。文档和迁移SQL进入仓库，私有数据与环境文件不进入Git。验证产物放 `/home/yao/artifacts/invention-atlas/<阶段>/<运行>`，运维说明继续维护在 `/home/yao/production/invention-atlas`。

本地开发库、测试库和生产库使用不同凭据。开发服务不得读取生产写入连接。调试默认使用模拟或合法导入数据；如需生产样本，采用一致性快照并控制访问，禁止测试清理脚本指向生产。

每阶段先通过本地验证，用户确认发布后提交和推送。代码采用不可变release，静态资源由现有 `scripts/prepare-release.mjs` 准备，避免重复嵌套public目录。生产数据、上传文件和模型配置均在shared或数据库中，不跟随release替换。

### 首次生产PG切换

1. 在生产建立独立PG服务/库与角色，检查磁盘及内存；不修改其他项目数据库。
2. 预演最终SQLite导入并验证应用。安排短维护窗口，暂停新任务、定时工作及所有数据写入；检查正在运行任务，先结束或明确保留为中断状态。
3. 获取SQLite一致性最终快照、私有配置与文件清单。此备份用于实质数据库迁移，必须保留到恢复验证通过。
4. 导入新PG库，核对业务字段和快照，检查序列及索引；记录迁移失败和处理结果。
5. 先以只读方式切换代码和数据库配置，验证登录、数据、历史、结果分页与报告导出。此阶段失败可切回SQLite，无新业务写入丢失。
6. 验证通过后启用PG写入，执行一组明确批准的新增/修改任务，确认事件流与历史保存正确。
7. 对PG执行备份并恢复到独立验收库，确认新写入也可恢复。保留旧SQLite快照和上一代码release，记录新的回退边界。

开放PG写入后，旧SQLite不含新数据。此后回退优先恢复PG备份并使用兼容的前一代码版本；若必须退回SQLite，需暂停写入并实现、验证PG新增数据的反向导出，不能直接切回旧文件。M1完成前保持schema变更向后可用，避免只保留一个无法连接PG的代码回滚目标。

之后的发布用版本化SQL迁移先增后用，删除旧字段在确认无引用后单独执行。每次发布核对当前与回滚代码的schema兼容性；数据库备份不能随旧release清理。只保留一个代码回滚版本的既有约定继续执行，必要迁移备份的保留期单独确认。

### 运维与管理

检查API与worker分别是否工作，HTTP200不能证明队列有消费者。告警覆盖持续失败、队列积压、索引中断及磁盘不足。日志按任务追踪，不记录密钥或完整私有材料；成员授权及删除等关键管理操作留记录。

模型配置按平台、组织及允许的用户配置分层，不在迁移时擅自更换现用模型。任务记录模型与调用参数，成本按组织和项目归属；设置任务预算、并发及取消行为。上传解析与嵌入任务也计入成本。备份频率和恢复时间目标在容量试验后确定并演练。

| 实现离线迁移 | scripts目录（待建） | 导入及核对报告 | 修正映射后重建独立目标库 |
| 全功能本地验收 | tests与浏览器验证 | 统计对照、历史及导出记录 | 修复差异，不进入生产切换 |
| 恢复演练 | 独立恢复库 | 备份恢复记录、切换手册 | 演练未通过则阻止发布 |

后续每阶段更新需求表状态，并链接实际代码提交和验收记录。用户确认阶段交付后再推进生产，避免连续多阶段改造后一次性替换在线平台。
