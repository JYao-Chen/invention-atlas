Invention Atlas 面向已入库专利的研究分析。系统通过检索确定研究范围，计算文献的时间分布和主体结构，再结合技术主题、引证关系、科学论文关联及权利要求组织报告。公开编号连接计算结果与原文，便于核对代表文献及具体技术措施。

平台有两个互不混用的入口。查询工作台直接运行29项分析工具，参数、进度和结果都留在本页；分析助手由 LangGraph 智能体根据自然语言安排工具，执行计划、结构化结果和模型解释保存在对话中。统计、图网络和关键词方法对比由 TypeScript 程序计算，模型只用于规划、主题命名、全文辅助抽取和报告撰写。报告可以逐条人工复核，复核结果按章节和工具汇总。

## 用相同演示数据快速开始

需要 Node.js 22.16+（22.x）和 Docker Compose。在新克隆的仓库中执行：

```sh
npm ci
npm run setup
npm run demo:import
npm run dev
```

另开终端运行 `npm run worker`。打开 <http://127.0.0.1:3017>，用 `.env.local` 中生成的账号和密码登录。初始化脚本创建本项目的独立数据库；导入命令下载固定版本的3400条专利及向量，同时安装论文资料和两份示例报告。数据导入和示例查看无需模型凭证；使用助手时配置自己的接口。

数据包下载、导入选项及来源许可见[演示数据说明](docs/DEMO-DATA.md)。

## 01 数据准备与研究范围

数据导入支持规范化 JSONL、Google Patents JSONL、USPTO XML 及 Derwent/WoS 文本。系统保留来源，按公开编号去重，分别保存 IPC 与 CPC，以及申请人和受让人。数据概况展示各字段的覆盖情况。

数据概况汇总记录数、公开年份和字段覆盖率，用于判断后续方法是否具备输入条件。质量审计检查必要字段、日期及重复编号，并核对已有权利要求的原文偏移。审计结果按专利与问题类型列出，支持逐项定位。

![数据与索引管理](public/help/desktop-data.png)

记录支持新增、编辑和删除，可勾选跨页记录批量删除，也可删除整个数据集。语义索引按批保存进度，停止后可继续处理未完成记录。标题或摘要修改后，需要重建该条向量；数据修改不会重算已保存报告。

分析可以限定公开年份、申请人及 IPC。公开件口径保留各公开版本；同族代表件按来源标识归组，选取范围内最早公开件，缺标识的记录独立保留。跨工具比较应保持范围和口径一致。

当前在线库有三个数据集，均来自 [ExponentialScience/DLT-Patents](https://huggingface.co/datasets/ExponentialScience/DLT-Patents)：区块链专利库 3000 条（2018—2025 年）、专利样本库 300 条、公开语料采集 100 条，合计 3400 条，去重后 3287 个公开编号。资料按技术主题定向筛选。固定版本演示包可通过 `npm run demo:import` 下载，保留相同的专利记录和向量。同族和法律状态字段保留来源信息。

## 02 专利检索与检索评价

专利检索建立与技术问题相关的候选集合。系统将问题转为嵌入向量，按标题摘要向量的余弦相似度排序，支持中文问题检索英文文献。运行前需建立索引；返回数量控制候选集规模。

输入技术对象或用途，设置范围及返回数后执行。检索结果展示标题摘要及相关性排序，候选集可继续用于领域统计。

检索策略比较使用 BM25 词法匹配，对多组表达计算交集和独有命中。保持范围及返回数一致，打开差异文献判断补充术语的作用。结果展示各策略的命中数量与集合重合率。

![检索结果](public/help/desktop-search_patents.png)

专利详情按公开编号读取摘要、权利要求和说明书，同时显示已有分类及来源链接。点击结果编号或图谱节点可打开详情。申请公开与授权公开属于不同版本，条款应分别阅读。

检索效率实验记录一次 AI 检索或人工布尔检索的查询式、起止时间和命中公开编号，再与研究人员提供的参考集对照查准率和查全率。参考集只用于本次计算，不保存。

## 03 公开活动与技术分类

公开趋势按公开日期统计数量，用于描述语料中的公开活动。设置时间粒度和年份范围后，通过图表比较分布。比较前查看各年度的记录数量与采集范围。

生命周期统计对年度累计公开量进行 Logistic 拟合，至少需要六个有记录的公开年。结果同时展示观测量、拟合曲线、参数和误差。

![生命周期统计](public/help/desktop-analyze_lifecycle.png)

IPC 分布按 IPC 分类代码整理技术构成。选择分类层级后查看频次与对应文献。一项专利的多个分类分别计数。公开局分布按编号前缀统计文献来源地域。

## 04 关键词与技术主题

关键词词频从标题摘要提取 TF-IDF 关键词，同时保留原始词频 TF 和文档频次 DF。词云用于观察术语分布，柱状图及数据表用于核对数值。显示指标可以切换，数量滑块调整已有结果的可视项数，点击词语查看指标。权重反映术语在所选语料中的区分作用。

每个词关联实际包含它的公开版本，年度结果仅关联对应年份。词云详情显示文献标题和命中片段，可打开原文。报告从词项关联文献中选择示例。旧结果未保存关联时需重跑工具。

年度关键词在各公开年提取高权重术语，用于比较文本关注点。范围内全部文献参与计算，结果行是归纳后的“年份—关键词”组合。例如八个年份、每年十词对应八十行结果。

关键词突现识别词语在时间序列中的集中出现，供研究阶段性关注变化。结果同时提供词频、突现区间及对应文献。

主题聚类使用标题摘要嵌入向量与固定种子的 K-means。设置主题数后，模型结合组内关键词及代表文献命名。PCA 投影形成二维散点图；颜色对应主题，点击主题可筛选，点击专利点读取原文。实际聚类在高维空间完成，二维投影保留的解释方差显示在坐标轴上。

![技术主题聚类](public/help/desktop-analyze_clustering.png)

关键词方法对比在同一语料中运行 TF-IDF、TextRank 和单词版 YAKE，输出各自排名、两两 Jaccard 重合度、示例专利和耗时。Jaccard 重合度描述不同方法关键词集合的一致性。算法细节见[关键词方法对比](docs/METHOD-COMPARISON.md)。

## 05 申请人结构与竞争格局

申请人组合比较主体在技术分类中的分布，用于识别集中方向及跨领域布局。竞争者演化按年份追踪主体公开活动，描述语料内的主体结构变化。比较采用已确认的名称归并规则，排名按文献数量计算。

申请人集中度计算 CR3、CR5 和 HHI，分别描述头部主体份额与整体集中程度。有效主体数由 Shannon 熵的指数计算。指标按所选语料及计数口径计算。

合作网络依据同一公开件中共同出现的主体建立连接。选择主体类型后检查节点与边权，并读取共同申请文献。

![申请人合作网络](public/help/desktop-analyze_co_network.png)

## 06 引证、科学论文与代表文献

引证网络保存来源中的真实引用边，区分样本内部文献和外部对象。节点及边用于追踪引用关系，再回到原文核对语境。内部被引数和 PageRank 根据所选引证网络计算。

共引分析寻找被同一文献共同引用的对象；文献耦合比较共享引用对象的文献。两者分别描述共同被引与共同引用关系，用于组织关联阅读。共享数量与对应文献共同展示连接关系。

![引证与关联图](public/help/desktop-analyze_citation_network.png)

引证技术主路径将合格内部引用整理为时间有序图，通过 SPC 路径权重提取连接，用于安排技术文献阅读次序。自引及不符合时序的边不参与计算。

引证指标筛查依据内部被引数和 PageRank 进行 Pareto 非支配分层，整理进一步阅读对象。结果列出两个引证指标与非支配层；来源交易金额按实际披露的组合范围记录。

科学论文关联来自 Reliance on Science 的专利—论文引用数据，论文标题、年份、期刊和被引次数来自 OpenAlex。在线库 3287 个公开编号中，822 个有论文关联，共 3494 条关联、2581 篇论文，其中 164 篇在 OpenAlex 没有元数据。数据页显示当前数据集的覆盖率，专利详情按置信度和被引次数列出关联论文。数据来源、子集构建和许可见[外部参考数据](docs/EXTERNAL-DATA.md)。

## 07 同族资料与全文分析

同族地域分析按来源成员编号统计公开局，保留文献与成员对应关系。同族标识用于归组，成员列表用于地域分析；成员缺失时在覆盖信息中列出，点击成员可查看相应公开版本与状态。

法律状态统计按来源获取时点整理状态与法律事件。获取日期、事件日期和预计到期日分别保存。

权利要求要素抽取读取指定公开版本和条款中的技术特征，保留连续引句及原文偏移。可以选择条款号，长文本按段处理并保存完成段。技术特征可跳转到完整条款中阅读。

权利要求对照以第一项编号为基准，比较其他文献，提供双侧引句与匹配结果。对象应具有相近技术内容，明确版本及条款范围。未找到对应时，可继续阅读说明书或扩大检索范围。

![权利要求对照](public/help/desktop-compare_claims.png)

技术效果矩阵读取摘要、权利要求及说明书，分段提取明确陈述的措施—效果关系，保留原文证据。相同参数重跑复用已完成段，矩阵中的措施和效果均关联原文位置。

## 08 查询工作台与分析助手

查询工作台按分组选择工具，填写范围和参数后在本页运行。宽屏时参数和结果左右并排，窄屏上下排列；每次运行保存为“工具 · 工具名”记录，从历史打开时回到工作台。“综合分析”按钮在本页依次运行数据概况、申请人组合、主题聚类、引证指标筛查、引证网络和权利要求要素，缺少字段的工具自动跳过。工作台运行不会打开分析助手，助手的运行也不会写入工作台结果区。

助手通过注册工具及 LangGraph 流程执行任务，外部宿主也可通过项目凭据调用MCP。先确定研究范围并安排必要工具，程序计算统计、整理原文证据，再由模型流式生成报告。明确指定的工具保留在计划中，范围和参数随运行保存。分类内的突现统计直接按 IPC 和年份限定语料。

报告撰写前，系统整理实际研究范围、公开年份覆盖、各工具的分析数量与计数口径、逐行代表专利及可用图表；需要时补读已计算结果的相关分页。范围概况按公开记录统计，各工具分别保留同族或筛选口径。模型依据这些数据组织发现、比较与原文解释。

限定领域的问题先检索，再由模型复核候选范围，最多补充检索两轮，剔除的候选保存理由。报告写完后，程序逐段核对正文中的公开编号、数值和图表引用能否在本次工具结果中找到；需要修订时保留当前正文，完成后一次更新。

前端将执行记录集中在可展开的“分析过程”中，显示计算状态、范围和报告准备情况。正文开始后该区域自动收起，文字和真实结果图表交替显示；没有被正文引用的结果在结束后补齐。停止、重试、历史恢复和保存报告仍保留各自的结果快照。

助手首页每批推荐四个问题，根据当前记录、可用工具、分类和年份随机设置分析范围。服务端保存三批库存，页面打开时直接显示；“换一组”立即取下一批，后台补充后续问题。模型仍按JSONL生成文案，但只更新备用批次，不改写用户正在阅读的问题。首次冷启动或模型不可用时使用已校验的定向问题，无需等待模型。新增、编辑、删除专利或更新索引后缓存失效。选中问题后保留其工具及参数，直接发送时按该计划执行；改写问题后按普通自然语言重新规划。

对明确单一 IPC 小类的词频、年度关键词或突现统计，例如“分析 H04L 在 2018—2025 年的关键词突现”，助手直接使用该分类及年份范围内全部匹配记录计算。未明确年份时保留数据实际覆盖；筛选结果显示匹配记录数。

回答完成后，模型结合当前问题、已有回答和可用工具生成五个相关追问。建议按 JSONL 流式解析，每完成一条即显示一条。点击可填入输入框，修改后再发送；“换一组”重新生成不同角度的建议。建议随对话保存，生成失败保留已返回项，不影响已完成的报告。

## 09 报告、复核与人机协同评测

对话历史从助手进入，分页恢复已保存任务。报告与对话均可单条删除或勾选批量删除；对话选择支持跨页，删除前会确认。删除对话保留已保存报告，删除报告不删除原对话或专利数据。

HTML 导出为独立文件，包含公式字体、完整工具结果和交互组件，可离线切换词云、图表、图谱、聚类与数据表，调整显示数量、年份和指标，查看词项与节点信息。图表可下载 SVG 或 PNG，原始结果可下载 JSON。点击专利编号打开来源网页需要网络。Markdown 保留文本。历史报告保留当次快照，不随切换数据集改变，历史运行明确标记。

报告库中每份报告都可以打开“逐条复核”。页面把报告拆成段落，列出每条结论引用的公开编号和工具结果；研究人员选择采纳、修改或驳回，修改和驳回必须填写理由，可以补充核对过的证据。提交后不可覆盖，改判时新建记录。统计按报告、章节和工具汇总三类比例和平均复核耗时，同一人对同一条只计最后一次提交。

工具选择离线评测集 `evals/tool-selection/questions.json` 有31道问题，覆盖全部29项工具，按固定种子分为开发集21题、测试集10题。评测脚本支持只检查划分的 dry-run；正式运行会调用规划模型，需要单独授权费用。字段与口径见[人智协作复核](docs/HUMAN-AI-REVIEW.md)。

## 10 专业研究任务

技术全景将公开活动、分类、主题和申请人结构置于同一确认范围，用于形成领域文献结构的综合研究。在专业任务入口选择技术全景，填写目标、数据集、年份与IPC，先检查范围概况，再确认候选。未指定主题表达时保留结构筛选记录；指定表达时使用语义召回并标注候选上限。

确认后执行公开趋势、IPC分布、年度关键词、聚类和申请人组合，逐项保存结果。证据阶段从结果关联中选择代表专利并读取原文，报告依据统计及保存证据生成。报告结合代表专利原文比较主题与主体分布。

竞争主体任务先确认申请人名称。完全匹配与近似候选分别显示，用户选择实际来源名称，近似名称不自动合并为集团。未匹配主体保留空结果，不以全库代替。确认相同年份和分类范围后，执行专利组合、年度演化和合作网络，形成逐目标主体的比较。

共同申请件分别计入对应主体组合，公开活动和类别变化用于比较主体布局。

技术方案查新以用户方案为输入，提取有方案引文的部件、步骤及关系，确认特征后编辑检索策略。策略支持布尔词项关系与语义召回，分别保存命中路径。指定年份和IPC约束候选范围，多条策略按公开编号去重，用户选择候选后执行全文对照。

对照逐件、逐批记录支持、部分对应或未找到对应，证据包含公开版本、原文字段和引文位置。修改状态或解释后先保存，再确认底稿。支持与部分对应需有实际引文。最终报告依据确认底稿汇总特征对应关系与原文证据。

专利布局任务从代表文献提取措施—效果关系，形成有出处的矩阵，再选择拟研究方向。来源关系、原文声明效果与模型建议分别标识。方向可以编辑、保存和取消全部选择；不选择方向时，报告仍可汇总已有证据。可根据矩阵与补检索记录继续研究候选方向。

各专业任务保存输入和阶段版本。修改前序产物使相关下游版本过期，避免旧统计配新方案。取消、执行失败或工作进程重启后，可以按已保存阶段续跑；重新生成报告复用已确认统计与证据，保留先前报告版本。

## 11 技术交底、原始材料与OCR

技术交底保存方案文本及修订版本，模型可针对已保存版本提出技术追问并关联所指原文。用户可根据追问补充方案描述。报告库中的原始材料入口接收PDF、DOCX、TXT和Markdown，保留原文件与提取文本。

扫描PDF可选择原文件页码执行OCR，界面显示运行进度和逐页结果。服务器配置MinerU Cloud后，新任务使用`vlm`模型；未配置时使用本地Tesseract。MinerU上传选定PDF分片，保存批次与页结果，中断后复用已完成部分，不在云端失败后静默切换引擎。页码映射回原文件，表格与公式文字保留在提取结果中。

从材料选择保存文本或已完成OCR页创建查新任务，输入随任务保存。背景技术与待研究方案分别记录。MinerU会接收选定PDF内容，敏感资料应在上传前确认授权；配置与分片限制见[MinerU OCR](docs/MINERU-OCR.md)。

标题摘要向量用于专利记录召回，全文向量用于权利要求和说明书片段定位。两类索引分别检查覆盖数量、模型和原文版本。更换嵌入模型需重建索引；全文检索按片段返回结果，并保留所属专利编号。

## 12 来源更新与持续监测

来源更新读取指定DLT源窗口，记录获取时间、窗口和入库批次。界面可查看下载进度、任务状态与各记录版本；已存在手工修订的记录遇到来源冲突时拒绝覆盖。配置更新计划后由后台到期提交，按指定来源和窗口执行。

监测订阅保存检索条件及运行间隔，可暂停、恢复和立即执行。修改表达或范围后保存新的策略版本并重新建立基线。站内通知保留新增、移出及字段修改前后的快照；失败或数据不足显示真实原因，不写成零变化。删除订阅不抹去已有研究记录。

## 13 组织协作、模型与开放接口

组织管理员创建项目和邀请，受邀账户加入组织后仍需分配项目权限。项目负责人管理成员，分析成员维护资料和执行任务，只读成员阅读授权记录。平台管理员管理账号启停与密码重置，不自动取得其他项目的资料。材料、数据集、对话、结果和报告均按项目隔离，切换项目后重新确认研究对象。

报告支持草稿版本、批注和固定发布快照。修订草稿不会覆盖已发布版，定向分享只授予指定快照的阅读，不授予原项目访问权。协作事项关联具体报告版本，可指派、处理和查看待办。

对话与报告均支持单条及勾选批量删除，删除对话不删除已保存报告，删除报告不删除原对话。Markdown交付正文，HTML保留离线图表交互、公式和数据下载；Word及PDF用于版面交付。

组织管理员可以配置本组织的兼容聊天接口与模型凭据，未配置时沿用平台模型。密钥由服务器加密保存，界面不回显；编辑时留空保持原密钥，删除组织配置恢复平台选择。全文嵌入沿用平台索引模型，不与组织聊天模型混用。

模型用量记录实际调用及提供方返回的token，任务预算限制调用次数。未知用量单独列出，聊天、嵌入与OCR费用分别由提供方计费。

管理菜单创建项目接口凭据，选择读取或写入权限及有效期，密钥只在创建时显示。凭据固定绑定项目，撤销或成员权限变化影响后续调用。OpenAPI描述接口；MCP提供29项分析工具和7项资源、任务操作，共36项，支持stdio与HTTP。公网HTTP端点为`https://patent.jyaochen.cn/mcp`，使用项目Bearer凭据。

外部宿主发现工具后按输入参数调用。耗时分析提交持久任务，再读取进度、结果及分页数据，停止需显式请求；断开客户端不取消已入队任务。自然语言调用依据工具目录、数据与参数执行。配置示例见[MCP接入说明](integrations/patent-mcp/README.md)。

报告结论、复核记录、检索实验、数据集外部覆盖率和专利关联论文都有对应接口，字段见 OpenAPI。

## 14 安装与配置

需要Node.js 22.16或以上、npm及独立PostgreSQL数据库。向量存储需要pgvector；PDF提取和OCR需要Poppler，MinerU结果读取需要unzip，本地OCR需要Tesseract及相应语言包，Word/PDF导出需要完整LibreOffice Writer/Math。

```sh
git clone git@github.com:JYao-Chen/invention-atlas.git
cd invention-atlas
npm ci
cp .env.example .env.local
```

在 `.env.local` 设置自己的账号和模型凭证，勿提交该文件。

```dotenv
PATENT_USERNAME=admin
PATENT_PASSWORD=your-own-password
DASHSCOPE_API_KEY=your-dashscope-api-key
PATENT_MODEL=qwen3.8-flash
PATENT_API_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
PATENT_EMBEDDING_MODEL=text-embedding-v4
PATENT_DATA_DIR=./data
DATABASE_URL=postgresql://atlas_runtime:your-password@127.0.0.1:5432/invention_atlas
QUEUE_DATABASE_URL=postgresql://atlas_queue:your-password@127.0.0.1:5432/invention_atlas
PATENT_MODEL_CREDENTIAL_KEY=your-64-character-hex-key
```

数据库迁移与管理员初始化使用维护连接。按[PostgreSQL说明](docs/POSTGRES-DEVELOPMENT.md)建立角色与权限，再执行以下脚本。脚本读取进程环境，执行前加载私有配置，并临时将`DATABASE_URL`指向维护连接；完成后恢复普通运行连接。

```sh
npx tsx scripts/migrate-postgres.ts
npx tsx scripts/initialize-admin.ts
```

Web的`DATABASE_URL`必须使用非表所有者且不能绕过行级权限的角色，`QUEUE_DATABASE_URL`用于后台跨项目领取任务。组织模型加密配置需要独立保存的64位十六进制密钥，不能使用示例占位文本。数据库备份与原始上传文件分别保留，加密密钥不放入公开仓库或数据库导出。

```sh
npm run dev
```

在另一个进程运行 `npm run worker` 执行后台任务。

打开 [http://127.0.0.1:3017](http://127.0.0.1:3017)。在“模型与设置”保存并测试连接，随后导入资料和建立索引。对话模型支持 OpenAI 兼容接口，名称应由提供商实际支持；语义索引使用独立的百炼嵌入配置。API 费用由对应提供商收取。

数据页可按源位置分批获取 DLT 公开语料。服务器无法直连时，可设置 `PATENT_DATASET_ROWS_URL` 为自管 `/rows` 转发地址。命令行 `npm run data:fetch` 直接请求官方接口，获取原始 300 条样本，已有该来源资料时不重复导入。`npm run data:index` 为当前数据集建立索引。与线上相同的固定演示数据通过 `npm run demo:import` 安装。

## 15 开发、测试与部署

```sh
PG_TEST_DATABASE_URL=postgresql://user:password@127.0.0.1:5432/atlas_test npm test
npm run typecheck
npm run build
npm start
```

应用采用 Next.js App Router、React、TypeScript、LangGraph 和 PostgreSQL。Web与后台工作进程分别运行，持久任务保存在PG队列中，不依赖Python或Redis服务。任务事件通过SSE传输；关闭页面不停止后台任务，用户取消后可按保存的阶段续跑。

账户采用邀请制，组织与项目分别管理成员，项目提供负责人、分析成员和只读成员角色。原始材料、专利、对话、报告及任务按项目隔离。组织管理员可配置本组织聊天模型；密钥在服务器加密保存，界面不回显。未配置的组织沿用平台模型，全文嵌入保持平台索引模型。

专业任务包括技术全景、竞争主体分析、技术方案查新和专利布局分析。各流程保留输入、研究范围及阶段产物；需确认的阶段允许用户选择、编辑、保存后继续。布局使用原文措施—效果关系形成矩阵，候选方向可选择是否纳入报告；查新支持从PDF、Word或文本材料创建输入，并可选择已完成OCR的原文件页码。

材料 OCR 支持 MinerU Cloud 的 `vlm` 模型，保留表格、公式及原始 PDF 页码，并保存上传批次和分片结果以便续跑。启用后材料会发送至 MinerU Cloud；凭据仅由服务器读取。配置、依赖和验证范围见 [MinerU OCR](docs/MINERU-OCR.md)。

开放接口使用项目凭据，支持OpenAPI、stdio与HTTP MCP。构建接入包用`node scripts/build-patent-mcp.mjs`，配置和权限说明见[integrations/patent-mcp](integrations/patent-mcp/README.md)。部署后台与迁移脚本用`node scripts/build-runtime.mjs`，普通Web连接与队列维护连接不得混用。

工具目录提供输入字段和参数说明，返回结果包含研究范围、逐行专利关联及原文证据。已保存结果可通过 `/api/results/{id}` 按 `offset`、`limit` 分页，按 `word`、`year` 筛选；`section=graph` 读取真实图谱边。报告传递指标定义与预览覆盖情况，必要时由模型选择补读最多四页，每页最多一百行。结果分页同时记录总量与当前展示量。

```text
src/components/   页面、表单、图表与使用说明
src/server/       工具计算、模型调用、任务与数据库
src/lib/          类型、说明书与结果布局
scripts/          数据获取、索引与验证脚本
tests/            算法与流程测试
public/brand/     品牌 Logo
public/help/      电脑与手机截图
data/             私有运行数据，不提交 Git
```

在线实例由一台 Linux 服务器以三个 systemd 用户服务运行 Web、后台任务和 MCP，经反向隧道提供 HTTPS 访问。发布时在独立工作树中检出指定提交，执行 `npm ci`、`npm run build`、`node scripts/build-runtime.mjs` 和 `node scripts/prepare-release.mjs`，把独立输出复制为新版本目录，再切换 `current` 链接并重启三个服务；上一版本目录保留用于回滚。数据库迁移由表所有者执行，Web 运行角色不能建表。数据库及模型配置放在发布目录之外。具体配置见[开发与部署说明](docs/DEVELOPMENT.md)。

外部参考数据用 `npx tsx scripts/external/build-all.ts` 构建。脚本先写入测试库的临时 schema，生成 JSONL 子集与来源清单，审核后再由维护连接导入正式库。步骤和容量记录见[外部参考数据](docs/EXTERNAL-DATA.md)。

使用说明维护在 `src/lib/help-guide.ts`，运行 `npx tsx scripts/prepare-help.ts` 同步仓库文档。截图来自真实保存结果，更新流程见[说明与截图维护](docs/DEVELOPMENT.md#更新说明与截图)。测试记录注明使用的数据与参数。
