# 核对与修订
用 research_state 查看章节发现，read_chapter 阅读受影响全文，再 read_result 或 read_patent 回到证据。事实判断不能只依赖前一章的模型摘要。

核对重复出现的年份、总数、分母、排名、集中度、主题组数量与名称。若不同工具因统计口径产生不同数字，实际阅读方法，解释各自测量的对象。不要为统一文字强行修改真实结果。方法排序不同先解释它们分别测量什么，不能直接判某种方法失效。单个关键词的覆盖率不能推出技术主题的数量；拟合的渐近量不能当成真实待公开存量；工具总行数须区分汇总行与明细行。派生增长率按明确公式重新计算。检查每个公开编号是否确在本次结果中，专利标题、申请人、公开日期与技术描述是否对应；主题成员查实际关联。份额、共现、引证与公开节奏分别解释其观察对象，涉及集团控制、团队归属或技术因果时读取相应证据。检查引文是否逐字来自登记位置。

删掉同一章和跨章没有新增信息的段落。对每个研发建议追问：来自哪个观察，针对哪个技术条件，下一步怎样验证？没有具体依据的建议重写或移除。内容不足时补充可回答研究问题的数据对照或原文案例。

通过 write_chapter 提交修订后的完整正文，保存版本并保留证据编号。修完后再核对受影响的交叉引用和摘要。需要整理中文表达时读取 chinese-style 技能，事实修正与语言整理分开完成。

所有章节实际完成、正文达到用户字数目标、主要结论有来源且跨章一致后，单独调用 finish_report。若工具指出不足，继续增加实质分析；不要只提交一句完成声明或缩短提纲规避任务。

交付前逐章追问：是否回答了一个研究问题，证据与结论之间是否有明确推理，是否解释了关键差异和其他合理解释？工具名称或指标列表主导章节时，按研究问题重新组织。只描述图表的章节需要补比较、案例或证据回查；引用放在具体受支持的陈述附近，检查来源是否实际包含对应事实。跨章论点相同而没有新增证据时合并表达，不能用新标题包装重复内容。

核对论断强度：相关关系是否被写成因果，样本结果是否被推广为行业总体，专利声明是否被写成已验证效果，未检出是否被写成不存在。“统计显著”须有检验、阈值和结果；“证明”“导致”“突破”“领先”“必然”须有相应证据及比较范围，否则回到具体观察或有条件的解释。保留相反证据和合理其他解释，不能只添加“可能”来保留无依据的断言。修订须保留影响结论的范围、成立条件与不确定性。

用 research_state 回看阶段记录，比较同一问题的早期判断与后续发现。关键缺口未解决时继续检索、分析或读取原文；若收窄结论已处理该缺口，正文和阶段记录交代对应变化。不要只修饰措辞而保留证据断裂，也不要把所有缺口列成通用免责清单。修改影响多章时更新相关章节与摘要的判断。
