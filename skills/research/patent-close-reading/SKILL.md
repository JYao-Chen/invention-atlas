# 原文研读
先查 research_state 中已登记的证据及阅读问题，通过 read_evidence 恢复已经覆盖问题的片段、位置与证据编号。为同一问题重复读取同一位置不会增加证据；已有片段足以回答时进入比较和写作。新问题先利用已读内容，只有缺少相应条款或上下文时才读取新的字段或位置。

用分析或检索结果选出与问题有关的公开编号。每次 read_patent 明确填写 question，按问题选择字段，不默认通读全文。记录字段、偏移和证据编号。寻找明确词句时，使用 read_patent 的 find 在指定字段内按字面定位，返回真实offset；未命中时调整词句或字段，不猜测位置。已有全文索引时，也可用 search_patent_passages 限定 patent_numbers 与 query 召回相关片段，保留其文档版本、字段、条款号和原始偏移。连续分页用于补充上下文，不为找一个词从头扫描整篇；分条权利要求的检索偏移与read_patent合并条款偏移分别记录。需要理解独立权利要求时先读 claims，再到 description 核查相应实施方式；不能仅凭标题还原技术方案。每次默认2500字符。证据足以回答问题时停止；缺上下文时按nextOffset续读，nextOffset为null时该字段已读完。需要多段文本时分页读取，不为几段原文调用整篇模型阅读工具。

解析对象、处理步骤、组件关系、约束条件与输出。技术效果要区分原文明确陈述、作者举例及本报告推断。把不同公开编号视作独立记录时，核查是否为同一申请的公开与授权文本；不要把同一方案两个版本当成两项独立创新。比较案例时用实际相同维度，而非每件都套一段“具有应用价值”。

短引文逐字保留，引用 [[source:证据编号]] 并加入 evidenceIds。不大段复制说明书；用自己的专业论述解释真实要素，不发明原文未给出的性能数字或法律效力判断。

read_patent_papers 提供的是已登记的专利—论文关系与论文元数据。用标题、年份、作者、来源链接讨论知识主题与时间连接；没有论文正文时，不写实验过程、实验结论或声称已经阅读全文。代表论文数量较多时按研究主题选择，不堆砌目录。核对题名、年份与原始链接是否对应；明显不相关或对应不上的条目回查原始引用，不自行编造正确题名。比较论文发表与专利公开的时间；较晚论文可作后续研究对照，知识来源判断须有对应的时间与引用依据。

技术效果矩阵 analyze_tech_matrix 会对所选每篇全文逐段调用模型。先确定研究所需的代表公开编号，通过 patent_numbers 每批1至5件显式指定；整体统计使用趋势、主题与主体工具。矩阵的解释范围对应所选案例，不能写成全库效果频率。

分析权利要求要素、全文问题手段效果与逐项权利要求对照同样需要明确选择专利；compare_claims至少两件，第一个是基准。能够用原文片段回答的问题，直接读片段；只有需要系统性全文整理时，才选择逐段模型工具。

按结论类型选择读取层次：统计规模与分组读分析结果；题名、日期、申请人和分类读已保存元数据；技术步骤读摘要定位后核查权利要求或说明书；条款构件和依赖关系直接读指定版本的权利要求；效果或实施条件读相应说明书段落。证据中只读了摘要，就按“摘要描述”表述；需要对照多个方案时，为每个方案分别保留来源与位置。回答涉及多个连续步骤时确认片段涵盖所述步骤，未覆盖的部分继续读取对应位置。
